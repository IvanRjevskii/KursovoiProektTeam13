## Как устроен рабочий день (процесс «как есть»)

Смены 3/3. Все приезжают утром, у всех две волны, все заканчивают вечером.

1. **Накануне** супервайзер закрепляет за водителем предварительный маршрут. Маршрут может меняться день ото дня; водитель может попросить закрепить за ним постоянный.
2. **Утро (≈ 6:30).** Водитель находит у механиков распечатанный на свою фамилию маршрутный лист.
3. **Предрейсовый медосмотр** на автоматическом терминале: алкотест, опрос по жалобам, давление, температура. Результат — наклейка на маршрутный лист.
4. **Механик** ставит печати, водитель расписывается за приёмку авто. Механик выдаёт папку: ключи, топливная карта, СТС, ОСАГО (иногда электронное).
5. **Фотоконтроль при приёмке** в приложении: каждый угол авто, приборная панель, запасное колесо, сумка с инструментами, акт приёма-передачи, текущий пробег.
6. **Загрузка, волна 1.** Водитель подъезжает к воротам, сканирует сетки в приложении и грузит отправления (тарники, россыпь, КГТ — сами сетки не грузятся). На практике отправления часто принимаются кнопкой «Принять без проверки».
7. **Развоз, волна 1** — обычно только передача в ПВЗ. В среднем ≈ 9 ПВЗ и ≈ 13 сеток.
8. **Загрузка и развоз, волна 2** — передача плюс забор возвратов. В среднем ≈ 13 ПВЗ и ≈ 17 сеток. На каждый ПВЗ выделяется 1–2 сетки.
9. **Сдача возвратов на складе.** Больше 250 позиций — работник склада сканирует одну, остальные засчитываются автоматически. 250 и меньше — самосдача на сканерах.
10. **Каждый 3-й день смены** после второй волны — заправка до полного бака по топливной карте на АЗС сети, выпустившей карту. Чек прикрепляется к маршрутному листу.
11. **Сдача авто.** Повторный фотоконтроль с пробегом на конец дня и остатком топлива. В маршрутный лист водитель вписывает пробег, остаток топлива и время прибытия, расписывается за сдачу и возвращает механику лист и папку.

**Нештатные ситуации.**
- **ДТП.** Водитель первым сообщает супервайзеру и решает вопрос с ним, а также главному механику — тот фиксирует ДТП (в том числе по фото повреждений второго автомобиля). Вызываются сотрудники ДПС, европротокол не используется. Супервайзер перераспределяет отправления водителя на других курьеров.
- **Повреждения при приёмке авто** разбирают механики.
- **Претензии** — штрафы водителю, например за привоз не на тот ПВЗ.

**Стажировка:** 2 дня стажёр ездит напарником с опытным курьером, затем несколько дней получает урезанные маршруты, после чего выходит на полные.

## Глоссарий терминов

| Термин | Значение |
|---|---|
| Маршрут | Список ПВЗ с сетками на каждую волну. Супервайзер закрепляет его за водителем накануне как предварительный |
| Маршрутный лист | Бумажный документ, дающий допуск к выезду на конкретную дату. Выпускает механик; на лист клеится наклейка медосмотра, на обратной стороне — акт приёма-передачи авто. После смены в него вносят пробег, остаток топлива и время прибытия |
| Предрейсовый медосмотр | Обязательная проверка водителя перед выездом на автоматическом терминале |
| Фотоконтроль | Фотофиксация автомобиля в приложении при приёмке и сдаче: углы кузова, приборная панель, запасное колесо, инструменты, акт, пробег (при сдаче — и остаток топлива) |
| Смена | Рабочий день водителя по графику 3/3: от приёмки до сдачи авто |
| Волна | Один цикл «загрузка на складе → развоз по ПВЗ → возврат на склад». В смене две волны |
| Задание | Действие на ПВЗ внутри волны: **доставка** (передача отправлений) или **забор** (возвраты). Статусы: в ожидании → в пути → прибыл → передано / забрано |
| ПВЗ | Пункт выдачи заказов. Идентифицируется числовым кодом |
| Сетка | Платформа на колёсах с сетчатыми стенками, в которой собраны отправления для одного ПВЗ. Номер — «ряд-место», например `14-02` |
| Тарник | Коробка ≈ 60×40×40 см с мелкими отправлениями |
| Россыпь | Крупные отправления, не поместившиеся в тарник, лежат в сетке отдельно |
| КГТ | Крупногабаритный товар (шины, стеллажи и т. п.), хранится в отдельной зоне склада, не в сетке |
| Возврат | Товар, который водитель забирает с ПВЗ во второй волне и сдаёт на склад |
| Код подтверждения | 4-значный код, который сотрудник ПВЗ называет водителю перед выдачей возвратов |
| Самосдача | Сдача возвратов на складе, при которой водитель сам сканирует каждую позицию |
| Приёмка без проверки | Подтверждение загрузки или возвратов одной кнопкой, без поштучного сканирования |
| Комплект документов | Папка, которую механик выдаёт с авто: ключи, топливная карта, СТС, ОСАГО |
| Топливная карта | Корпоративная карта для заправки на АЗС определённой сети |
| Перераспределение | Передача отправлений водителя другим курьерам (например, после ДТП) |
| Претензия | Штраф водителю за нарушение, например за привоз не на тот ПВЗ |

## Правила оформления диаграмм

1. Связи — **только** `Rel(от, кому, "бизнес-действие", "протокол")`. Макросы с направлением (`Rel` с суффиксами `_D`, `_U`, `_L`, `_R`) запрещены — сборка упадёт.
2. В своих файлах — никаких `skinparam`, цветов и шрифтов. Стили только в главном файле.
3. Каждая стрелка — конкретное действие («Выпускает маршрутный лист»), а не «Использует» или «Взаимодействует с».
4. У каждой диаграммы есть `title` и `LAYOUT_WITH_LEGEND()`.
5. У каждого элемента: название, для контейнеров — технология, и краткое описание.

```
.
├── .github/workflows/render-docs.yml   # CI/CD: проверка и отрисовка диаграмм (тимлид)
├── README.md                    # этот файл: процесс, глоссарии, правила
├── src/
│   ├── context/                 # L1: main-context.puml (тимлид) и <фамилия>-context.puml
│   ├── main.puml                # L2: сводная диаграмма контейнеров (тимлид)
│   ├── components/              # L3: <фамилия>-<контейнер>.puml
│   ├── code/                    # L4: <фамилия>-<компонент>.puml и <фамилия>_<модуль>.py
│   ├── landscape/               # L0: main-landscape.puml (тимлид) и <фамилия>-landscape.puml
│   ├── dynamic/                 # dynamic_process.puml (тимлид) и <фамилия>-dynamic.puml
│   └── deployment/              # main-deployment.puml (тимлид) и <фамилия>-deployment.puml
└── docs/images/                 # PNG — рисует CI автоматически
```

Фамилии в именах файлов — латиницей: `rzhevsky`, `chubchenko`, `ivanov`, `kobosnidze`, `krivenko`.
Имя после `@startuml` совпадает с именем файла — так PNG не перезаписывают друг друга.

## Как работать

1. Создай свою ветку: `feature/<фамилия>-labN` (N — номер лабораторной).
2. Положи свои файлы в нужные папки `src/` (см. структуру выше), названия — с фамилией.
3. Проверь, что схема рисуется без ошибок (Alt+D в VS Code).
4. **Коммить сам**, со своего аккаунта — преподаватель смотрит авторов коммитов и их даты.
5. Открой Pull Request в `main`, тимлид проверяет и сливает.
